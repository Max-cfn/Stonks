# Brief — Smoke test : endpoint /health du backend FastAPI

## Objectif
Créer le squelette du package `packages/backend` (FastAPI), avec un seul 
endpoint `GET /health` qui retourne `{"status": "ok", "version": "0.1.0", 
"service": "stonks-backend"}`. Inclure 1 test pytest qui vérifie ce contrat.
Pas de DB, pas d'auth, pas de feature business — juste prouver que la 
chaîne complète "code → test → CI → PR → merge" fonctionne avec toi.

## Contexte
- `packages/backend/` existe déjà comme stub (juste `pyproject.toml` + README)
- Phase 1 bootstrapée, monorepo pnpm + Taskfile, agents_core fonctionnel
- DeepSeek V4 Pro forcé sur provider DeepSeek officiel uniquement
- Aucun service infra (Postgres, Redis, Vault) ne doit être touché — 
  Phase 2 s'en charge plus tard
- GitHub repo cible : Max-cfn/Stonks. Branche `main` protégée → PR obligatoire.

## Critères d'acceptation
- [ ] `packages/backend/src/stonks_backend/main.py` créé avec FastAPI + endpoint /health
- [ ] `packages/backend/src/stonks_backend/__init__.py` exporte `__version__ = "0.1.0"`
- [ ] `packages/backend/tests/test_health.py` avec 1 test qui valide le payload exact
- [ ] `packages/backend/pyproject.toml` complété avec deps : fastapi, uvicorn, pytest, httpx
- [ ] `task setup` passe sans erreur après ajout
- [ ] `cd packages/backend && pytest tests/ -v` passe en local (utilise httpx.AsyncClient)
- [ ] CI GitHub Actions verte sur la PR
- [ ] PR ouverte vers main, pas de merge automatique

## Hors-périmètre
- ❌ Pas de Postgres, Redis, Vault, TimescaleDB
- ❌ Pas d'auth, JWT, ou middleware de sécurité
- ❌ Pas d'autre endpoint que /health
- ❌ Pas de modification de `apps/web`, `apps/mobile`, ni `agents_core/`
- ❌ Pas de modification de `.env` ou `.env.example`
- ❌ Pas de force push, pas de rewrite d'historique, pas de merge sur main
